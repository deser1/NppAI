# Isolated staged-code fitting with direct-response replay

Continue the **same own NppAI staged-mixture model** after the
[frozen diagnosis](stage-failure-diagnostic.md), keeping two explicitly different
objectives. This is an experiment in fitting/retention, not production promotion.
The [frozen protocol](../evaluation/staged-code-fit-v1.json) fixes the recipe
before evaluation and never increases the budget based on results.

Both arms start from checkpoint
`4859ad69e93ff2ca80d8951bca617476d118f8ef127abc4b313b8d2f0671c6fd`
in original artifact `12149182157`; the entire archive hash is verified before
loading. All **96 existing training records** and their authored specification,
plan and code targets remain unchanged. No held-out targets enter optimization.

| Property | Code only | Code with direct replay |
| --- | --- | --- |
| Updates | 512 | 512 |
| Shared base-task schedule | Seed43, 4 records/update | Identical |
| Objectives/update | Four code targets with authored priors | Two staged-code and two direct-code targets |
| Context / output | 1024 bytes / 128 generated bytes | Same |
| Optimizer | Fresh AdamW, learning rate 0.0003, clip 1 | Same |

Replay positions rotate across the sampled tasks. Equal updates/batch size do
not equalize staged-code exposure, target bytes, sequence lengths or compute.
Both actual token counts and all task/objective/loss traces are retained. The
model has **180,544 parameters**, two dense blocks, width64 and byte vocabulary256.
The experiment changes weights, not architecture or tokenizer.

## Measurement and acceptance

Before training, record direct, autonomous and authored-prior responses on all
96 training records. Train both arms to the final fixed budget. Then repeat the
training readout, conditional code/EOS readouts and exact-hit retention, and score
16 exposed v2 validation tasks and the existing six-task English/Polish suite
(12 correlated prompts). These are inspected regression sets, not a new pristine
benchmark. Original record hashes are checked unchanged.

Gold-prior code generation is **assisted**, and conditional target-byte prediction
provides correct target prefixes. Neither is autonomous quality. Direct generation
and the fully autonomous pipeline receive no reference-derived headers, renaming,
corrected plans or test answers. Preserve full outputs and failed cases.

The dedicated workflow executes regression candidates in the existing restricted
Docker validator, requiring all 12 authored reference controls to pass and a known
incorrect candidate to fail. No candidate executes on the host. Local measurement
uses `execution_status: not_run` because Docker is unavailable locally. The offline
auditor recomputes raw scores, conditional metrics, task schedules, per-case
retention, token accounting, exported-runtime checks and execution provenance.
Four fixed requests compare PyTorch with each exported dense-v2 production NumPy
checkpoint; evaluation must leave parameters unchanged. This does not certify
native INT8 or every possible runtime input.

## First local result

All values below describe **training reconstruction**, not unseen code quality.

| Exact replies, 96 training records | Before | Code only | Code + direct replay |
| --- | ---: | ---: | ---: |
| Direct task → code | 88 | 51 | 96 |
| Code with authored specification + plan | 16 | 92 | 86 |
| Fully autonomous stages | 2 | 0 | 1 |
| Retained original direct exact hits, of88 | — | 49 | 88 |
| Retained original autonomous exact hits, of2 | — | 0 | 0 |

Code-only gains two new direct hits but loses 39 original ones: the total51 is
not retention of51. Replay retains all88 and adds eight. Both arms retain all16
original assisted code hits. Even the replay model loses both original autonomous
hits; its one final hit is new, not retained.

The raw autonomous traces also show specification exact matches falling **12→1**
in both arms. Plan exact matches among actually generated plans fall **11→0**;
plan calls occur in 92 cases before, 76 after code-only and 73 after replay.
These artifacts are conditioned on the model's generated prior outputs, not
teacher-forced stage targets. This supports a narrow observation: direct replay
protects direct answers here, but does not preserve all stages.

Both arms remain **0/16 exact exposed-validation replies** and **0/12 exact
bilingual-regression replies** in autonomous and both direct evaluator controls.
Thus better assisted training fit is not improved generalization. We do not select
or install either checkpoint as the plugin default.

## Reproduce

```sh
python -m unittest discover -s tests -p 'test_staged_code_fit*.py' -v
python scripts/staged_code_fit.py --archive original-pilot.zip --output measured \
  --image sha256:YOUR_LOCAL_VALIDATOR_IMAGE
python scripts/audit_staged_code_fit.py measured
```

Omit `--image` only for explicitly recorded non-executing readouts. CI uploads both
research checkpoints, before/after records, traces, parity and Docker diagnostics
as `nppai-staged-code-fit`. The [development priorities](model-quality-development.md)
separate measured findings, next experiments and literature-supported hypotheses.

Raw local before/after responses, conditional bytes and full training traces are
retained in [code-fit-records.zip](evidence/staged-protocol/code-fit-records.zip),
with [member/checkpoint hashes](evidence/staged-protocol/code-fit-source.json).
Extract and run `python scripts/audit_staged_code_fit.py PATH` for an offline audit.
Candidate weights are supplied through the dedicated Actions artifact.
