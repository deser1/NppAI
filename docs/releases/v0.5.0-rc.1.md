# NppAI v0.5.0-rc.1

This is an **experimental prerelease** of the editor integration and installation
flow. It is not a promotion of the model as a reliable coding assistant.

## Included

- Windows x64, x86 and ARM64 plugin ZIPs, including the Python validation helper.
- A separate `NppAI-service.zip` with the own-model inference service, launcher,
  inference-only dependencies, Polish setup guide and factorial test cases.
  A repository checkout and PyTorch are not needed for inference.
- A separately downloadable `NppAI-research-staged-mix.nppai`, its model card
  and SHA-256. This is the unchanged research checkpoint used by installation CI.
- Automatic local/server routing, bounded repair attempts, Docker-backed Python
  validation, visible proposal/diff, guarded Apply/Reject and Unicode fixes.

## Start

1. Close Notepad++. Extract the matching plugin ZIP and place its `NppAI` folder
   in the editor's `plugins` directory. Back up an existing plugin first.
2. Extract `NppAI-service.zip` to a writable folder. Download the research model
   separately and compare its SHA-256 with `MODEL_CARD.md` or `SHA256SUMS.txt`.
3. Open PowerShell in the extracted service folder:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-inference.txt
.\.venv\Scripts\python.exe scripts\start_nppai.py --model "C:\Models\NppAI-research-staged-mix.nppai" --notepad "C:\Program Files\Notepad++\notepad++.exe"
```

Keep the console open. Follow `docs/notepad-setup-pl.md` for Docker Desktop and
authored validation cases. Without validation, Apply remains disabled.

## Evidence and limitations

The publication gate builds all three architectures, checks actual ZIP contents,
and launches x64 in official portable Notepad++ 8.9.8.1. The own-model service
runs from the extracted service ZIP rather than a repository checkout. The smoke
checks readiness, real menu/panel controls and a Polish prompt round trip.
The release also waits for successful CI_build on the exact source commit.

The supplied model achieved **0/12 functional passes** on six bilingual tasks
in the retained staged-protocol evaluation. Experimental continuations also
remain 0/12. Training fit is not evidence of useful new-task generation.
See the model card and linked reports; inspect every proposal and test result.

Not certified here: upgrade behavior, the user's Docker Desktop setup, GUI
Apply after successful validation, or actual x86/ARM64 editor execution. There
is no recording claiming that the model successfully generates a working program.

The release contains SHA-256 checksums and the machine-readable installation
report. The test is a reproducible integration demonstration, not a human demo
or proof of autonomous programming.
