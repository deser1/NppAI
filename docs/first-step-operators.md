# First-step CPU operator localization

The [training reproducibility investigation](training-reproducibility.md) located a first-update difference between recorded AMD and Intel runners, but did not isolate an operator. This diagnostic runs only the first fixed training batch from the same pinned source and resampled schedule, with seed 42, AdamW lr=0.001 and gradient clipping at 1.0. No development prompts, generated candidates or functional tests are used; no weights are promoted.

## Predeclared checks

Four independently provisioned runner jobs per existing runtime profile (`historical-v1`, `portable-cpu-v1`) each perform one ordinary first update and two traced repetitions from freshly loaded, identical starting weights. The eight-job allocation is fixed in advance; do not rerun until a preferred vendor or a green result appears. Actual CPU/vendor coverage is reported, not assumed from runner labels. This adds operator observation only; runtime profile definitions and historical checkpoint guards remain unchanged.

Require exact equality of initial and updated parameter hashes, raw and clipped gradient hashes, logits and hexadecimal loss between each traced update and its untraced reference. Require same-host event trace equality. Abort if observation changes the update; such a trace cannot explain the original training failure. Compare all six pairs of runner jobs within each profile only after checking identical source, batch, inputs, targets and initial parameters. The comparison job is a localization diagnostic: equal traces or limited vendor coverage are explicit outcomes, not successful model-portability gates.

[PyTorch's TorchDispatchMode](https://docs.pytorch.org/docs/stable/notes/extending.html) records observed ATen operations in forward, loss, backward, clipping and optimizer phases. Record schema, scalar arguments, shape/stride/dtype and SHA256 fingerprints of exact input/output tensor bytes. Unique snapshots are stored by content hash with a 128 MiB budget per trace; exceeding it fails explicitly. Allocation outputs and write-only destination contents are not read, since uninitialized memory is not a numerical result. Non-ATen profiler scope handles are excluded and their call counts retained separately; they are not numerical tensor results. Snapshot helpers run inside the mode handler, which excludes this same mode, avoiding recursive instrumentation.

A first different output for an identical observed operator call and identical recorded inputs localizes a difference at that boundary. Different schemas, call ordering or input fingerprints do not isolate an operator kernel and are labeled accordingly. Identical inputs do not reveal which internal vector instruction, BLAS kernel or reduction implementation caused a difference. Observed ATen boundaries are not every internal CPU instruction, and a single fixed first step does not prove complete-training repeatability.

Artifacts retain event traces, bounded raw tensor snapshots and complete environment/build provenance for 14 days. Raw snapshots may contain initial model parameters and are not committed or promoted. Durable result evidence should retain operator/input/output fingerprints, environment metadata, artifact digests and traced/untraced checks, with limitations. Measured results follow.


## Measured localization

[Run 38905715952](https://github.com/deser1/NppAI/actions/runs/38905715952) completed all eight trace jobs. All three actual Torch tests passed on each runner; all full-source steps preserved their untraced reference and repeated exactly (737 observed events). The cloud comparison initially failed from an unnecessary top-level training dependency; the same saved JSON traces were compared locally after making imports lazy. The comparison path is now tested under `python -S`, without third-party site packages. It does not require Torch or Pydantic. Tensor blobs are uploaded separately from the small event/report index in subsequent runs.

| Profile | Actual CPU coverage | Pairwise outcome |
| --- | --- | --- |
| historical-v1 | two AMD EPYC 9V45 (AVX512), two EPYC 7763 (AVX2) | four mixed-model pairs differ at event index 36; matching-model pairs identical |
| portable-cpu-v1 | four AMD EPYC 7763 (DEFAULT) | all six pairs identical; no cross-model/vendor coverage in this profile |

The first different historical event is `aten._softmax.default`, schema `aten::_softmax(Tensor self, int dim, bool half_to_float) -> Tensor`, in the first attention forward pass. All 36 preceding event records match. The call uses identical FP32 causal attention scores of shape `[4,177,177]`, dim=-1, half_to_float=false, but output bytes differ. This is observed operator-boundary evidence, not a BLAS/MKL or individual-instruction attribution.

Selected raw input/output ZIP members from replicas 1 and 3 were read and CRC-checked. Their dtype/shape/content hashes match the recorded tensor keys, and input bytes are directly identical. Among 125316 output elements, 17197 differ; maximum absolute delta is 5.960464477539063e-08 and maximum positive-FP32 ULP delta is 4. Both outputs are finite. These are small numerical differences, not an accuracy ranking or a new code-generation result. Whole 80 MB archive digests were not independently streamed/verified; GitHub-reported archive digests are retained and clearly distinguished from verified selected-member hashes.

This allocation contained no Intel host. It shows a boundary across AMD generations/dispatch capabilities, so vendor name alone is insufficient to define compatibility. It does not directly identify the earlier AMD–Intel difference or prove that the candidate DEFAULT profile fixes it. Initial source, batch and targets match; final first-step parameter hashes diverge in the mixed historical pairs. No baseline, arithmetic implementation or model promotion was changed.

[Retained comparison](evidence/first-step-operators/comparison.json), [manifest](evidence/first-step-operators/manifest.json), per-run reports, ordered event-fingerprint chunks, prefix contexts through event 36, and [selected softmax member verification](evidence/first-step-operators/selected-softmax.json) preserve the measured finding. Fingerprints verify the recorded common prefix and first differing event; full raw snapshots/event records remain in the 14-day artifacts and cannot be reconstructed from fingerprints alone. Next: measure isolated softmax alternatives and backward behavior on the same fixed inputs, with explicitly observed cross-vendor coverage, before changing the training recipe.


## Validation with Intel coverage

[Run 38906998886](https://github.com/deser1/NppAI/actions/runs/38906998886) passed all nine localization jobs, including the stdlib-only cloud aggregation. All five contract/actual Torch tests passed in each trace job, and each recorded source update again exactly preserved its untraced reference. Historical samples included EPYC 7763 and 9V74 and reproduced the first attention-softmax difference at index 36. Portable samples included EPYC 9V74, EPYC 7763 and Intel Xeon Platinum 8573C, all using DEFAULT dispatch.

In the portable profile, the three AMD traces match exactly. Each AMD–Intel pair has identical event records 0–522 and first differs at index 523: `aten.sqrt.default`, schema `aten::sqrt(Tensor self) -> Tensor`, during AdamW. The FP32 input has shape `[256,64]` and is byte-identical across the selected EPYC 9V74/Intel pair. This locates this recorded cross-vendor first-step difference in the optimizer phase rather than the forward/backward/clip phases, whose event records and gradient fingerprints match in this comparison.

Selected raw members were CRC-checked, checked against recorded dtype/shape/content keys and directly compared. Among 16384 sqrt output elements, 276 differ, by at most one positive-FP32 ULP; maximum absolute delta is 5.820766091346741e-11. Both outputs are finite. All differing elements have normal positive inputs; none has a subnormal input, so this finding does not support attributing this particular difference to subnormal-input flushing. It still does not identify an internal instruction or establish which result is more accurate. No arithmetic replacement was tested or promoted.

All eight small index ZIP SHA256 digests and the comparison ZIP digest were fully verified locally. Raw tensor archive digests remain GitHub-reported; only selected raw members were independently read and verified. [Validation comparison](evidence/first-step-operators/validation-comparison.json), [manifest](evidence/first-step-operators/validation-manifest.json), per-replica reports/event fingerprints and [sqrt member verification](evidence/first-step-operators/selected-sqrt.json) retain this second allocation alongside the first, without overwriting either outcome. This verification follows fixes to import isolation and artifact layout, without changing the arithmetic profiles or first batch. Next work must test both attention softmax and AdamW sqrt alternatives on the frozen inputs and complete updates, retaining the historical baseline and strict identity gates.

Subsequent raw-tensor uploads retain only the canonical first repetition, reducing duplicate storage; both complete event traces remain in the small index, and exact trace/update repetition remains required. Tensor keys identify identical snapshot bytes across the repetitions. This artifact-layout change does not change arithmetic or the retained earlier archive paths.
