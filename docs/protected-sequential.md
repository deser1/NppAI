# Protected vocabulary and sequential source cursor

This fixed pilot follows the frozen transition diagnosis. It compares the v1
soft pointer with a changed Python-only decoding mechanism, with the same
portable-both64 initialization and the vocabulary/hidden model frozen for **all
512 updates** in both arms. There is no production/default/weight promotion.

## Predeclared comparison

`evaluation/protected-sequential-v1.json` fixes input and schedule hashes before
measurement. Both arms use the namespace pilot's diverse schedule: two original
and two renamed TRAIN examples per update, seed 42, head seed 4242, 128 prefix
warmup updates for renamed targets only, then full targets. Original targets
remain full code throughout. AdamW uses lr .001, betas .9/.999, eps 1e-8,
weight decay .01, gradient clipping 1. There is no teacher KL or parameter search.

* **frozen_soft:** unchanged v1 prompt-only mixture with response NLL,
  all-name source-position NLL and .1 response gate BCE.
* **frozen_sequential:** response NLL, first-name source-start NLL and .1
  name/exit BCE. A hard cursor supplies subsequent source bytes during training;
  source alignment and correct response prefixes are TRAIN supervision only.
  The first byte retains a differentiable soft source pointer. Exit sees frozen
  query/source hidden states, initial zero weights and bias 4.

The comparison bundles cursor, loss-query and protection changes. Updates and
examples match; head dimensions, initial readouts and compute do not. It cannot
attribute an outcome to a single factor. Initial full-code results are recorded
separately for both arms. Frozen base hashes and absent gradients are checked at
every update; each arm repeats from initialization and must match all trace and
bundle bytes before evaluation. Native FP32 head arithmetic is not covered by
the earlier both64 cross-CPU numerical result.

## Explicit runtime mechanism and safeguards

Generation starts with an empty assistant response. If autonomous bytes become
exactly `def `, the sequential head selects one source start by learned attention
across prompt bytes, without a function-name parser, reference or supplied
scaffold. It copies the selected byte, then increments an absolute source cursor
one byte per copy. Duplicate and UTF-8 bytes remain separate positions. A learned
sigmoid on query/cursor hidden states exits at >= .5; exit delegates the current
and all subsequent decisions to the unchanged vocabulary argmax. An unavailable,
NUL, rolled-out or out-of-prompt cursor also delegates. There is no re-entry.
Generated bytes never enter the source mask. Source keys and query states are
causal; no future response is read at runtime. At training, the exit query has
the gold cursor immediately after the name, including the prompt's `(` byte.
The model must learn this boundary; runtime does not force `(` or validate a name.

The trigger and monotonic cursor are **explicit decoding assistance**, not an
unchanged autoregressive architecture or evidence of learned monotonicity.
This mechanism has a distinct `nppai-sequential-copy` version-1 bundle. The old
v1 loader rejects it; neither format is native-compatible. Safe bounded ZIP,
array shape/dtype/finiteness and digest checks apply. Production code is unchanged.

## End-to-end gates

Both arms greedily generate at most 160 bytes with rolling 256-byte context,
EOS 0, no output rewrite, repair or supplied prefix. Report full raw responses,
name-prefix, requested signature, AST/reference and exact-response scores on
132 exposed development views, 16 original and 16 renamed TRAIN views, and 64
unseen aliases from TRAIN task families. These are correlated diagnostics, not
fresh task accuracy. Exact-hit retention reports which prior cases were lost,
retained or gained, rather than comparing only totals. Inference parameters are
hashed before/after. Sequential raw bytes and cursor/exit events are retained.

Six already-exposed functional probes use the existing immutable local Docker
validator with isolation and cleanup checks. They are regression checks; no new
holdout is opened. A future candidate requires all original exact hits retained,
better complete development replies and functional improvement before a frozen
candidate can proceed to genuinely fresh broader evaluation. This pilot never
promotes automatically, even if those gates happen to pass.

## Measured result

Measurement run [39036199267](https://github.com/deser1/NppAI/actions/runs/39036199267)
used Python 3.12.15, Torch 2.14.1+cpu and an observed AMD EPYC 7763.
Artifact `12102426032` ZIP SHA256 is
`35d8a994d589fbe7776013e20a8d38a3c7e5281195e2f1fb6c4387f1f1d4e074`.
The initialization is the pinned portable export documented in the protocol;
this single measured allocation does not establish cross-vendor repeatability.

Both arms completed all 512 updates twice, with byte-identical same-host traces
and bundles. Every exported base is byte-identical to the pinned starting
`.nppai`, and evaluation leaves all parameters unchanged.

All 27 development exact replies come from the **44 natural-name views**:
14/16 validation and 13/28 test. The 88 renamed/matched-prefix development views
still yield **0 exact replies and 0 requested names**. Names/signatures above
therefore must not be read as namespace-invariant copying or fresh task accuracy.
The sequential TRAIN-family prefix breakdown is uneven: exact replies are
0/16 `nc_`, 9/16 `id_`, 2/16 `q_`, 0/16 `rename_`. Those are unseen suffixes on
known training references, not unseen task families. The sequential arm retains
all four original exact hits and gains ten others; the soft arm loses one.
The sequential alias name-prefix count is 21/64, distinct from 11/64 complete
replies and from AST-validated requested names. Its Docker failures comprise
three syntax failures, two functional failures and one empty response; the soft
arm has five functional failures and one empty response.

The frozen sequential mechanism improves complete replies and exact-hit
retention under this fixed comparison, but fails the functional gate and the
renamed development diagnostics. **No promotion.** This is a bundled mechanism
result, not evidence that a hard cursor alone or base freezing alone caused it.
No new holdout was opened and no settings were tuned to these outcomes.

Raw complete replies, sequential bytes/events and all 513 trace rows per arm
are reconstructed from `docs/evidence/protected-sequential/manifest.json` and
independently audited with `python scripts/audit_protected_sequential.py`.
Original ZIP SHA256/CRC, repeated raw bundles/traces, exported base bytes, input
exposure, loss components, source boundaries, cursor increments, exit decisions,
raw emitted bytes, scoring and retained/lost/gained counts are verified.
Weights remain in 14-day Actions artifacts; retained hashes alone cannot
reconstruct them.
